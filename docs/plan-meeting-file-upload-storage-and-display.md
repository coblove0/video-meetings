# Plan: Загрузка файлов встречи и их отображение внутри страницы встречи

**PRD:** @docs/prd-meeting-file-upload-storage-and-display.md
**Дата:** 2026-07-29

## Фазы реализации

### Фаза 1: Модель данных и загрузка файла (tracer bullet)

**Цель:** Заложить фундамент — Prisma-модель для файлов встречи и минимальный рабочий путь загрузки одного файла: сохранение содержимого на диск и метаданных в БД, с проверкой владельца и валидацией размера/типа.
**Затрагивает:** backend, database
**Задачи:**

- [ ] Добавить в `schema.prisma` модель `MeetingFile` (originalName, size, mimeType, storagePath, createdAt, `meetingId` FK на `Meeting`) и сгенерировать миграцию
- [ ] Создать `MeetingFilesModule` по образцу `MeetingsModule` (CQRS: `impl/`/`handlers/`), настроить multer (`diskStorage`) с лимитом размера файла и allowlist MIME-типов
- [ ] Реализовать `UploadMeetingFileCommand`/`Handler`: проверка, что встреча принадлежит текущему пользователю (`findFirst` по `id`+`ownerId`, иначе 404), сохранение файла на диск и метаданных в БД
- [ ] Добавить `POST /meetings/:id/files` (`JwtAuthGuard`, `@CurrentUser()`, `FileInterceptor`) — при превышении лимита размера или недопустимом типе файл не сохраняется ни на диске, ни в БД, возвращается понятная ошибка
- [ ] Покрыть unit- и e2e-тестами: успешная загрузка, отказ не-владельцу (404), отказ по размеру/типу

**Когда готова:** Файл, загруженный через `POST /meetings/:id/files` владельцем встречи, физически лежит на сервере, а его метаданные — в таблице `MeetingFile`; запрос от чужого пользователя получает 404; файл сверх лимита размера или недопустимого типа не сохраняется нигде и возвращает понятную ошибку.

### Фаза 2: Список, скачивание и удаление файлов

**Цель:** Дополнить backend оставшимися операциями над файлами встречи — просмотр списка, скачивание содержимого и удаление, с той же проверкой владения.
**Затрагивает:** backend
**Задачи:**

- [ ] `GetMeetingFilesQuery`/`Handler` + `GET /meetings/:id/files` — список файлов (имя, размер, MIME-тип, дата загрузки), только для владельца
- [ ] `DownloadMeetingFileQuery`/`Handler` + `GET /meetings/:id/files/:fileId/download` — стриминг содержимого файла с корректными заголовками (`Content-Type`, `Content-Disposition`)
- [ ] `DeleteMeetingFileCommand`/`Handler` + `DELETE /meetings/:id/files/:fileId` — удаление записи из БД и файла с диска
- [ ] Единообразная проверка владения (`findFirst` по `meetingId`+`ownerId`) во всех трёх ручках, отказ для не-владельца
- [ ] e2e-тесты: список/скачивание/удаление работают для владельца; для чужого пользователя — отказ во всех трёх ручках

**Когда готова:** Владелец встречи может через API получить список файлов, скачать содержимое любого файла и удалить файл (запись и содержимое пропадают); те же запросы от другого пользователя возвращают отказ.

### Фаза 3: Страница встречи со списком файлов

**Цель:** Дать владельцу встречи UI для просмотра списка файлов, их скачивания и удаления.
**Затрагивает:** frontend
**Задачи:**

- [ ] Создать `/meetings/[id]` (`page.tsx`, client component), guard по `accessToken` в `localStorage` как в `src/app/page.tsx`, редирект на `/auth/login` при отсутствии токена
- [ ] Получить данные встречи (`GET /meetings/:id`) и список файлов (`GET /meetings/:id/files`), обработать отказ доступа (редирект/сообщение об ошибке)
- [ ] Отрисовать список файлов (HeroUI-компоненты): имя, размер, MIME-тип, дата загрузки
- [ ] Добавить скачивание файла (запрос с Bearer-токеном к download-ручке) и кнопку удаления с подтверждением; после удаления файл пропадает из списка без перезагрузки страницы; добавить переход на страницу встречи со списка встреч на главной (`src/app/page.tsx`)
- [ ] Настроить `@playwright/test` в apps/web (конфиг, npm-скрипт `test:e2e -w web`; отразить новый раннер в `apps/web/CLAUDE.md` и корневом `CLAUDE.md` § Commands) и написать e2e-тест: владелец видит список файлов (имя, размер, MIME-тип, дата), скачивает и удаляет файл; отдельный тест — пользователь, не являющийся владельцем, при прямом переходе по URL на `/meetings/:id` получает отказ доступа

**Когда готова:** Владелец встречи открывает `/meetings/:id`, видит список загруженных файлов (имя, размер, дата), может скачать и удалить любой файл прямо со страницы; сценарий, включая отказ доступа не-владельцу, покрыт автоматическим e2e-тестом (`npm run test:e2e -w web`).

### Фаза 4: Загрузка файла со страницы встречи

**Цель:** Замкнуть пользовательский сценарий — загрузка файла прямо со страницы встречи без перезагрузки.
**Затрагивает:** frontend
**Задачи:**

- [ ] Добавить на страницу встречи форму загрузки: выбор одного файла + кнопка загрузки
- [ ] Отправить файл через multipart `POST` на `/meetings/:id/files` с Bearer-токеном, показать индикатор процесса загрузки
- [ ] После успешной загрузки добавить новый файл в список без перезагрузки страницы; ранее загруженные файлы не затрагиваются
- [ ] Показать понятную ошибку при отказе backend (превышен размер/недопустимый тип); файл не должен появляться в списке
- [ ] Добавить e2e-тест (Playwright, `npm run test:e2e -w web`, раннер из Фазы 3): загрузка файла → появление в списке без перезагрузки → повторная загрузка не затрагивает предыдущие файлы → загрузка недопустимого файла (размер/тип) показывает ошибку и не добавляется ни в список, ни на backend

**Когда готова:** Владелец встречи выбирает файл на своём устройстве, загружает его — файл тут же появляется в списке без перезагрузки страницы; повторная загрузка добавляет ещё один файл, не затрагивая предыдущие; весь сценарий, включая ошибку валидации, покрыт автоматическим e2e-тестом.
