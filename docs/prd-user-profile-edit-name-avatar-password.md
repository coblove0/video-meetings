# PRD: Профиль пользователя — редактирование имени, загрузка аватара, смена пароля

**Дата**: 2026-07-31
**Статус**: Draft

## Цель

Пользователь должен иметь возможность просматривать и редактировать данные своего профиля (имя, аватар) и самостоятельно менять пароль, не обращаясь к администратору.

## Пользовательские сценарии

- Пользователь открывает страницу профиля -> видит текущее имя, аватар (или заглушку, если не загружен) и email
- Пользователь меняет имя и сохраняет -> новое имя отображается в профиле и в остальном интерфейсе, где используется имя пользователя
- Пользователь выбирает файл изображения и загружает его как аватар -> новый аватар отображается в профиле и в остальном интерфейсе, где используется аватар пользователя
- Пользователь загружает файл, который не является изображением или превышает допустимый размер -> получает понятную ошибку, аватар не меняется
- Пользователь открывает форму смены пароля, вводит текущий и новый пароль, сохраняет -> пароль обновляется, при следующем входе действует новый пароль
- Пользователь вводит неверный текущий пароль при попытке смены -> получает ошибку, пароль не меняется
- Пользователь, не прошедший аутентификацию, обращается к странице профиля или API профиля -> получает отказ в доступе

## В скоупе

- Страница профиля в apps/web, доступная только аутентифицированному пользователю (собственный профиль, без просмотра чужих профилей)
- Поле `name` в модели User (одно текстовое поле — полное/отображаемое имя), редактирование через форму
- Загрузка аватара: файлы JPG/PNG, лимит 5MB; хранение по тому же принципу, что и файлы встреч (`apps/api/src/meeting-files` — локальный диск, `randomUUID()`-имя, `fileFilter` по MIME-типу)
- Замена аватара: повторная загрузка заменяет предыдущий аватар (не история версий)
- Отображение текущего аватара (или заглушки, если не загружен) и email (только для чтения) на странице профиля
- Смена пароля: форма с полями «текущий пароль» и «новый пароль»; смена возможна только при верном текущем пароле
- Валидация нового пароля по тем же правилам, что уже применяются при регистрации
- Проверка доступа: читать и изменять профиль (имя, аватар, пароль) может только сам аутентифицированный пользователь, только для собственной учётной записи

## Не в скоупе

- Смена email пользователя
- Удаление аккаунта
- Восстановление/сброс пароля через email (пароль меняется только из авторизованной сессии, зная текущий пароль)
- Разлогинивание других активных сессий после смены пароля
- Уведомление пользователю (email/push) о смене пароля или аватара
- Разделение имени на отдельные поля (имя/фамилия) — используется одно поле «Имя»
- Обрезка/редактирование изображения аватара на клиенте или сервере (кроп, ресайз) — сохраняется файл как есть в пределах лимита
- Просмотр или редактирование профиля другого пользователя, публичные профили
- Двухфакторная аутентификация и прочие меры безопасности аккаунта сверх смены пароля

## Технические ограничения

- User в Prisma-схеме сейчас содержит только `id`, `email`, `passwordHash`, `createdAt`, `updatedAt` — потребуется миграция для полей `name` и ссылки на аватар (файл/URL)
- Auth-модуль (`apps/api/src/auth`) и Users-модуль (`apps/api/src/users`) построены на CQRS (`@nestjs/cqrs`); новые операции (обновление профиля, смена пароля) должны следовать этому же паттерну команд/запросов, а не прямому вызову между модулями
- Пароли уже хранятся хэшированными через `bcrypt` (`passwordHash`) — смена пароля должна использовать тот же механизм хэширования
- Хранилище файлов — только локальный диск (`UPLOAD_DIR`), без S3/облака, как и для файлов встреч; аватар хранится по тому же принципу
- Аутентификация — JWT (`JwtAuthGuard`, `@CurrentUser()`) — эндпоинты профиля должны быть защищены этим же guard'ом

## Критерии готовности

- [ ] Аутентифицированный пользователь может открыть страницу профиля и увидеть своё текущее имя, аватар (или заглушку) и email
- [ ] Пользователь может изменить имя, сохранить изменение, и оно отображается после обновления страницы
- [ ] Пользователь может загрузить JPG или PNG файл до 5MB как аватар, и он отображается как текущий аватар
- [ ] При загрузке файла не-изображения или файла больше 5MB загрузка отклоняется с понятным сообщением об ошибке, текущий аватар не меняется
- [ ] Повторная загрузка аватара заменяет предыдущий, а не добавляет новый
- [ ] Пользователь может сменить пароль, указав верный текущий пароль и новый пароль; после сохранения вход возможен только по новому паролю
- [ ] При неверном текущем пароле смена пароля отклоняется с ошибкой, пароль не меняется
- [ ] Неаутентифицированный запрос к странице или API профиля получает отказ в доступе
- [ ] Пользователь не может прочитать или изменить профиль другого пользователя через API
