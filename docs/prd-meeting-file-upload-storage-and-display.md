# PRD: Загрузка файлов встречи и их отображение внутри страницы встречи

**Дата**: 2026-07-29
**Статус**: Draft

## Цель

Владелец встречи должен иметь возможность загрузить файлы, связанные со встречей (запись самой встречи и произвольные файлы участников — документы, презентации и т.п.), чтобы они надёжно сохранялись и были доступны для скачивания на странице этой встречи.

## Пользовательские сценарии

- Владелец встречи открывает страницу конкретной встречи -> видит список уже загруженных для неё файлов
- Владелец встречи выбирает файл на своём устройстве и загружает его -> после завершения загрузки файл появляется в списке файлов встречи
- Владелец встречи загружает ещё один файл (по одному за раз) -> новый файл добавляется в список, ранее загруженные файлы не затрагиваются
- Владелец встречи открывает файл из списка -> файл скачивается
- Владелец встречи удаляет ранее загруженный файл -> файл пропадает из списка и удаляется из хранилища
- Пользователь, не являющийся владельцем встречи, открывает страницу встречи или обращается к API файлов -> получает отказ в доступе (список файлов, загрузка, скачивание и удаление доступны только владельцу)

## В скоупе

- Минимальная страница отдельной встречи в apps/web (сейчас существует только список встреч на главной), доступная только владельцу встречи
- Загрузка файла на встречу: единый механизм для записи встречи (видео/аудио) и произвольных файлов участников (документы и т.п.) — без разделения на типы на уровне API
- Загрузка ровно одного файла за операцию; повторная загрузка добавляет новый файл, а не заменяет предыдущий
- Список загруженных файлов на странице встречи: имя файла, размер, MIME-тип, дата загрузки
- Скачивание загруженного файла
- Удаление ранее загруженного файла владельцем встречи
- Хранение метаданных файла (имя, размер, MIME-тип, дата загрузки, связь со встречей) в базе данных
- Хранение содержимого файла на сервере (конкретный backend хранилища — вопрос реализации, не часть этого PRD)
- Ограничение по размеру файла и допустимым типам файлов при загрузке
- Проверка доступа: загружать, просматривать список, скачивать и удалять файлы может только владелец встречи (ownerId)

## Не в скоупе

- Автоматическая обработка файла: транскрипция, распознавание речи, анализ содержимого, генерация саммари — отдельная будущая фича поверх метаданных, зафиксированных в этой итерации
- Загрузка и удаление файлов участниками, не являющимися владельцем встречи (participants сейчас — строки email/имени без аутентифицированной привязки к User)
- Одновременная/пакетная загрузка нескольких файлов одним действием (drag-n-drop сразу нескольких файлов, очередь загрузок)
- Встроенная запись видеозвонка и автоматическая загрузка результата (в проекте пока нет самой функции видеозвонка; предполагается загрузка уже готового файла с устройства пользователя)
- Версионирование файлов и редактирование метаданных после загрузки
- Воспроизведение video/audio и любой другой предпросмотр содержимого файлов в браузере — только хранение и скачивание
- Уведомления о загрузке файла другим участникам встречи

## Технические ограничения

- В Prisma-схеме нет модели для файлов встречи — требуется новая модель со связью на `Meeting`
- `Meeting`/`User` сейчас не имеют relation для participants как пользователей (только строки email/имени) — доступ к файлам может проверяться только по `ownerId`
- Страницы отдельной встречи (`/meetings/:id` или аналог) в apps/web ещё не существует — создаётся в рамках этой фичи
- В apps/api нет инфраструктуры для загрузки и хранения бинарных файлов (multer или аналоги) — добавляется с нуля
- Необходимо определить и enforced-проверить максимальный размер одного файла и список допустимых типов файлов

## Критерии готовности

- [ ] На странице конкретной встречи владелец видит список всех загруженных для неё файлов (имя, размер, дата)
- [ ] Владелец встречи может выбрать и загрузить один файл, после чего он появляется в списке без перезагрузки страницы
- [ ] Загруженный файл сохраняется на сервере, а его метаданные — в базе данных, связанные с конкретной встречей
- [ ] Владелец встречи может скачать любой файл из списка
- [ ] Владелец встречи может удалить загруженный файл, после чего он пропадает из списка и удаляется из хранилища
- [ ] Пользователь, не являющийся владельцем встречи, получает отказ (403/404) при попытке получить список файлов, загрузить, скачать или удалить файл через API
- [ ] При попытке загрузить файл сверх установленного лимита размера или недопустимого типа пользователь видит понятную ошибку, а файл не сохраняется ни в базе, ни в хранилище
